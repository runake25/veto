# Veto console — UI audit, 2026-10-26

Two independent, read-only designer-auditors walked every screen and component state at
1440×900, 1024×768 and 390×844, captured 100+ screenshots, and probed the DOM (contrast,
focus rings, hit sizes, overflow, semantics) before any code changed. Their full reports are
in `/tmp/ui-audit/report.md` and `/tmp/ui-audit-system/` on the machine that ran the audit;
this file keeps the verdict, what was fixed, and what is deliberately left for a later round.

Scores at audit time: **6.5/10** system surfaces (design craft 8.5, product hardening 5.0) and
**7/10** Overview / Inbox / Record. The visual world (framed sheet, graphite desk, navy rail,
one type scale, tabular money, honest copy) was judged genuinely authored; the gap was
interaction completeness around the edges.

## Fixed in this round

- **Sheet width:** the late `.screen { max-width: 100% }` override that stretched every screen
  past its 1080px measure is gone.
- **Inbox density and table ergonomics:** rows tightened (57px → ~47px), the header is sticky,
  hover is a real target cue, and the order control is now one always-visible `Order` select
  ("Needs you first", newest/oldest, amount high/low, agent A–Z/Z–A) with the same vocabulary
  on desktop and mobile. Header Agent/Amount/Created remain sort shortcuts.
- **Inbox reconciliation:** the list now returns and shows a footer strip — `1–14 of 14` and
  the filtered `$4,358.92 total` — so a queue can be added up, not just counted.
- **Inbox recovery:** error bar has Retry; an empty filter state offers "Show all requests";
  the count stays visible at 390px; filter chips scroll on one line instead of wrapping.
- **Mobile record cart:** vendor, quantity and unit price are no longer dropped at ≤720px —
  lines stack and keep the evidence the policy reasons cite.
- **Irreversible actions:** Approve, Veto and Void now open an inline confirmation that names
  the amount and the consequence; on mobile the actions stack instead of sitting side by side.
- **Month envelope:** Overview asks the approver's second question — "Left this month" with
  `$885.93 of $2,850.00 committed` — replacing the Agents stat. The header action is now
  "Review requests" instead of the demo lever "Try a cart".
- **Ledger vocabulary:** the record kicker no longer leaks enums (`policy · review · awaiting`
  → `policy · needs a signature · Needs you`), and origin + channel are shown as separate
  provenance facts.
- **Analytics:** zero is no longer painted green, Held keeps one tone across screens, chart
  value labels stop colliding with bars below 1280px, and the daily series has a
  screen-reader-only data alternative.
- **Browser surfaces:** text selection now survives the navy rail and filled buttons, the rail
  gets a light focus ring (8.2:1), select controls use the tokenised input skin, the copy
  buttons meet the 24px target, scrollbars/caret are themed, and every `.btn` has press
  feedback. Rail label contrast lifted past 4.5:1.
- **Expired-consent lifecycle:** a lapsed consent leaves "Needs you" (Overview needs-you is
  signable-only), gets its own Inbox tab and row label, and the record offers **Send it again**
  (creates a fresh request through the same agent and pipeline). `GET /overview` reports
  `expired_consents`, and the request list takes `consent=actionable|expired`.
- **Freshness:** Overview and the Inbox show `Updated HH:MM · Refresh` and poll every 30s while
  the tab is visible.
- **Inbox search:** title/text/agent/requester search, URL-addressable, with a clear recovery.
- **Agent brake:** pause/resume on the agent page with an inline confirm; paused agents refuse
  new requests.
- **Standing job card:** the agent page now shows the routine the backend and Slack already
  had — cadence, next run, the month's envelope track (spent / unsigned / left), the reorder
  window, the recorded runs with outcome, amount and record link, a streamed **Run now**
  behind a confirm, pause/resume and an inline editor for instruction, cadence, envelope and
  window. The roster plate carries one line per job ("runs every week" / "job paused").
- **Job provenance:** a request raised by a routine reads **Routine** in the Inbox source
  column and `Routine · Pantry restock` on the record kicker, instead of the transport label
  "API key".
- **The brake is a money rule now:** `requests.create` refuses a paused agent from every
  door; routing skips paused agents, and a due routine records a skip instead of ordering
  while the agent is paused.
- **Viewer on the agent page:** rules, pause, the job and its runs are read-only for the
  viewer role, matching the record, instead of offering buttons the API would refuse.
- **Small hardening:** skip link + per-route document titles, real favicon, 72ch prose measure,
  dry-run result honours `prefers-reduced-motion`, API-key revoke is a two-step confirm that
  names the consequence, and the 404 record has a heading and a Retry.

## Fixed in the polish round (2026-10-26, later the same day)

Every deferred finding was closed, one by one, with a regression harness
(`tools/check_polish.py`, 20 read-only HTTP checks) and a fresh screenshot set at 1440,
1024 and 390.

| Severity | Finding | What changed |
|---|---|---|
| L | Inbox had no vendor/date search | `q` now also matches `request_lines.vendor` and line titles; the filter bar has a **When** control (today, 7 days, 30 days, this month) computed in the viewer's calendar and sent as `from`/`to`/`tz`, so a capture after local midnight lands on the right day. |
| M | Refresh was manual/polled on two screens; Slack approvals did not push to the board | New `GET /api/v1/events` SSE change feed (`veto/events.py`) with bounded per-tab queues and a 20 s heartbeat; `FreshnessProvider` re-reads the current screen on a change frame, on tab focus and on a 30 s fallback. The header control reads `Updated HH:MM · Live` while connected. |
| L | A standing job could not be deleted, nor an agent | `DELETE /api/v1/agents/{id}/routine` removes the job and its run history; `DELETE /api/v1/agents/{id}` removes an agent **only when it has no recorded requests** — otherwise `409 agent_has_history` names the count and says "Pause the agent instead". Both are two-step confirmations that state the consequence; the ledger is never touched. |
| S | Run-now live panel showed settlement only in the final frame | `Settlement.capture(on_step=…)` plus `requests.create` progress frames; a run streams extract → catalogue → price → decision → **record → consent → order → authorization → capture** → run. Same panel component as the dry run (`components/live.tsx`). |
| M | Boot mapped a network failure to the sign-in screen; inline errors had no Retry | The session check now has its own `BootFailure` state — heading, cause, "Try again", "Continue to sign in" and the free-instance wake note. Overview, Inbox, Agents, Analytics, Integrations, the agent page and a record all carry Retry. |
| M | Mobile (<900px) lost wallet state, identity and sign-out | A topbar account menu (avatar → identity, workspace, role, wallet state, wallet & integrations link, sign out) replaces the hidden rail below 900px; the phone top nav gets its own full-width row below 560px. |
| M | Three status languages and "can't buy"/"active" split | One `State` component and one vocabulary module (`components/state.tsx`): request status, agent state, job state, run outcome, integration state, payment state and payment mode all render dot + word with the same four tones. The dry-run verdict is the single larger instance; pills and the raw `agent-state`/`run-outcome` classes are gone. |
| M | No `aria-sort`/table semantics on the Inbox grid; chart had no visible data table | The Inbox is a real `<table>`: sticky header cells own the sort buttons, `aria-sort` sits only on the active column, each row's title is a link, and a phone gets the same rows as a list. Analytics has a **View the daily numbers** disclosure with a day / captured / requests table. |
| M | Agent form had no inline validation and surfaced server copy far from the field | Field-level rules mirror the API (name and length limits, dollars and cents, merchant domains, category slugs, the category exception pair), errors render under their field with `aria-invalid`/`aria-describedby`, the first invalid control is focused, and a server message that names a field is placed beside it. |
| M | Integrations left a large empty column and a sparse keys card | Slack sits beside a stacked wallet + model-routing column with the keys card full width; the skeleton mirrors the new grid. |
| M | Revoking a key had no success feedback | Revoking now shows a `role="status"` line naming the consequence ("That agent's next request is refused with 401"). |
| S | Ledger identifiers were inert; payment status showed raw `COMPLETED` | A `CopyValue` control (order, authorization, capture, cart hash, record id) copies the full value while the row stays readable; `COMPLETED` reads "Completed", mode reads "PayPal sandbox" / "In-process simulator". |
| S | Skeletons did not mirror the final block geometry | Inbox (table + phone rows), record, agent page, analytics and integrations skeletons now match the blocks that replace them. |
| S | Copy nits: mono `sandbox`/`COMPLETED`, 9.5–10px meta | No meta text below 11px; `Sandbox · USD` is a word, not a mono tag; payment words are humanised. |

Two follow-ups that were open in the same table are also done: the chart's value labels
stop colliding (only bars with room get a label; every day is in the data table), and the
account menu is the mobile answer to the rail.

## Remaining, deliberate

- Free-plan hosting: an idle Render instance sleeps after 15 minutes and loses its
  ephemeral history. The GitHub keep-alive workflow and the demo reseed exist for that;
  a paid always-on instance is the only way to remove the risk entirely.
- The Inbox window is a closed set of ranges (today / 7 days / 30 days / this month) rather
  than two free date pickers; custom ranges are the obvious next step if a queue ever needs
  them.
- A record's cart on a phone keeps the vendor, quantity and unit price (the audit's earlier
  fix) but still reflows into a tall card; a compact two-column layout would be the next
  pass.
