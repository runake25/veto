# Veto console — UI audit, 2026-10-26

Two independent, read-only designer-auditors walked every screen and component state at
1440×900, 1024×768 and 390×844, captured 100+ screenshots, and probed the DOM (contrast,
focus rings, hit sizes, overflow, semantics) before any code changed. Their full reports are
in `/tmp/ui-audit/report.md` and `/tmp/ui-audit-system/` on the machine that ran the audit;
this file keeps the verdict, what was fixed, and what is deliberately left for a later round.

Scores at audit time: **6.5/10** system surfaces (design craft 8.5, product hardening 5.0) and
**7/10** Overview / Inbox / Record. The visual world (framed sheet, graphite desk, navy rail,
one type scale, tabular money, honest copy) was judged genuinely authored; the gap was
interaction completeness around the edges.

## Fixed in this round

- **Sheet width:** the late `.screen { max-width: 100% }` override that stretched every screen
  past its 1080px measure is gone.
- **Inbox density and table ergonomics:** rows tightened (57px → ~47px), the header is sticky,
  hover is a real target cue, and the order control is now one always-visible `Order` select
  ("Needs you first", newest/oldest, amount high/low, agent A–Z/Z–A) with the same vocabulary
  on desktop and mobile. Header Agent/Amount/Created remain sort shortcuts.
- **Inbox reconciliation:** the list now returns and shows a footer strip — `1–14 of 14` and
  the filtered `$4,358.92 total` — so a queue can be added up, not just counted.
- **Inbox recovery:** error bar has Retry; an empty filter state offers "Show all requests";
  the count stays visible at 390px; filter chips scroll on one line instead of wrapping.
- **Mobile record cart:** vendor, quantity and unit price are no longer dropped at ≤720px —
  lines stack and keep the evidence the policy reasons cite.
- **Irreversible actions:** Approve, Veto and Void now open an inline confirmation that names
  the amount and the consequence; on mobile the actions stack instead of sitting side by side.
- **Month envelope:** Overview asks the approver's second question — "Left this month" with
  `$885.93 of $2,850.00 committed` — replacing the Agents stat. The header action is now
  "Review requests" instead of the demo lever "Try a cart".
- **Ledger vocabulary:** the record kicker no longer leaks enums (`policy · review · awaiting`
  → `policy · needs a signature · Needs you`), and origin + channel are shown as separate
  provenance facts.
- **Analytics:** zero is no longer painted green, Held keeps one tone across screens, chart
  value labels stop colliding with bars below 1280px, and the daily series has a
  screen-reader-only data alternative.
- **Browser surfaces:** text selection now survives the navy rail and filled buttons, the rail
  gets a light focus ring (8.2:1), select controls use the tokenised input skin, the copy
  buttons meet the 24px target, scrollbars/caret are themed, and every `.btn` has press
  feedback. Rail label contrast lifted past 4.5:1.
- **Small hardening:** skip link + per-route document titles, real favicon, 72ch prose measure,
  dry-run result honours `prefers-reduced-motion`, API-key revoke is a two-step confirm that
  names the consequence, and the 404 record has a heading and a Retry.

## Deferred (documented, not fixed)

| Severity | Finding | Why deferred |
|---|---|---|
| L | **No freshness/refresh** anywhere; counts go stale after Slack/API actions | Needs a poll/visibility design across Overview/Inbox; touches every read screen |
| L | **Inbox has no search** (title/vendor/agent/date range); history is only filterable | New API surface + query syntax; next product round |
| L | **Expired consent lifecycle:** `awaiting` requests with an expired consent still count as "Needs you", but approve is closed and there is no re-request CTA | Needs a derived "expired" state in the API and lists, plus a re-request action; touches consent semantics |
| L | **Agents cannot be paused from the console** (API accepts it; no kill switch in the UI) | Needs a header action + confirm + list treatment; next round |
| L | **Standing jobs have no UI** though the backend, scheduler and Slack commands exist | The routine card belongs under Guardrails; next round |
| M | Boot maps a network failure to the sign-in screen (dead end) and inline errors lack Retry | Needs an app-level error state; on the next pass |
| M | Mobile (<900px) loses wallet state, identity and sign-out (no account menu) | Needs a topbar account menu; the audit asks for it before calling mobile done |
| M | Three status languages (dot+word, coloured pills, dry-run outcome pills) and "can't buy"/"active" naming split | Requires one shared status component across agent, dry-run and record surfaces |
| M | No `aria-sort`/table semantics on the Inbox grid; chart is `role="img"` with no visible data table | A real table (or ARIA grid) is a structural change; summary text was added as a stop-gap |
| M | Agent form has no inline validation and surfaces raw server copy far from the field | Needs a field-level validation pass; error copy was left as the API returns it |
| M | Integrations layout leaves a large empty column and a sparse keys card | Needs a layout decision (Slack spans rows / wallet + keys paired) |
| M | Revoking a key is confirmed now, but there is no success flash/undo path | Small follow-up, not test-critical |
| S | Ledger identifiers are inert text (no copy affordance); payment status shows raw `COMPLETED` | Next polish pass |
| S | Skeletons do not mirror the final block shapes (Inbox, agent detail, record) | Needs per-screen skeleton geometry |
| S | Copy nits: `Try a cart` removed, but a few mono tags (`sandbox`, `COMPLETED`) and 9.5–10px meta remain | Next polish pass |
